# สรุปผล B2 Security (สำหรับสไลด์)

**คำถาม:** pod แบบ Kata แยกตัวออกจากเครื่อง worker ได้มากกว่า pod ธรรมดา (runc) จริงไหม

**วิธีทดสอบ:** สร้าง pod `nginx:alpine` 2 ตัวบนเครื่องเดียวกัน ต่างกันแค่ runtime แล้วดูว่าจากในตัว pod มองเห็นอะไรบ้าง

| ดูอะไร | runc | Kata | หมายความว่า |
|---|---|---|---|
| เคอร์เนล | `7.0.0-1014-aws` (ของเครื่อง) | `6.18.35` (ของ VM) | Kata มีเคอร์เนลแยก ไม่ได้ใช้ร่วมกับเครื่อง |
| RAM | 7776 MB (ทั้งเครื่อง) | 192 MB | Kata ไม่รู้ว่าเครื่องจริงมี RAM เท่าไร |
| CPU | 2 (ทั้งเครื่อง) | 1 | Kata เห็นแค่ CPU ของ VM |
| รุ่นเครื่อง | `m8i.large` | อ่านไม่ได้ | runc รู้ว่ารันบน EC2 รุ่นไหน Kata ไม่รู้ |
| `dmesg` | ถูกห้าม | อ่านได้ แต่เป็น log ของ VM | ยืนยันว่า Kata มีเคอร์เนลของตัวเอง (และ pod รู้ว่าตัวเองอยู่บน QEMU/KVM แต่ไม่รู้ข้อมูลเครื่อง worker) |

```
runc:  [nginx] ── เคอร์เนล worker (ใช้ร่วมกัน) ── เครื่อง
kata:  [nginx] ── เคอร์เนล VM ── qemu ── เคอร์เนล worker ── เครื่อง
                  └─ ชั้นกั้นที่เพิ่มขึ้น ─┘
```

**สรุป:** Kata เพิ่มชั้นกั้นอีกหนึ่งชั้นระหว่าง pod กับเครื่อง และทำให้ pod รู้ข้อมูลเครื่องจริงน้อยลง ถ้าเคอร์เนลมีช่องโหว่ คนที่อยู่ใน pod แบบ runc มีโอกาสหลุดถึงเครื่องได้ตรง ๆ ส่วน Kata ต้องเจาะ VM ให้ได้ก่อน (ไม่ได้แปลว่าปลอดภัย 100% แค่ยากขึ้นอีกชั้น)
